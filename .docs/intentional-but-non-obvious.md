# Intentional but Non-Obvious

This document outlines application behaviors that are intentional but non-obvious, and deemed too in-the-weeds for the top-level [`README.md`](../README.md)

- Rollup behaviors: the active checking takes into account the Profile's order in the list; the first profile matched takes prescendence.  There are a number of things that trigger off of the active checks, like when to skip switching to a Profile on launcher activation.  With audio-only profiles vs the main profiles, there may be some unexpected 'switch' when clicking a launcher, even if the profile is fundamentally unchanged just because of the way profile activity is calculated between the two.  For most use cases, there is no real drawback to an additional switch action, and there may actually be some benefits to allowing the sort to decide how this happens, especially if users are mainly using this for audio selection.
- Profile deltion will **ASK** the user if it should also delete connected shortcuts.  By contrast, application uninstall _tries_ to delete **ALL** known shortcuts (along with config and logs, etc.), and does so automatically without asking for confirmation after the uninstall confirmation.  In both cases, shortcuts which have been intentionally moved or renamed are considered 'owned' by the user and should not be touched by the application uninstall.
- Set audio device really only allows you to connect to things or create profiles for thigns which are currently acessible.  This is a design feature, but might not be obvious, say if you want to set up audio for a TV soundbar before that device becomes accessbile; in most cases turning on the TV  on its own may not be enough to make that soundbar ; you may have to actually connect the TV as a display before the soundbar attached to it will be seen (might depend on connection mechanics, like HDMI vs optical, not tested).  There is no issue connecting to the soundbar generally while the TV is connected as a display; once created, these profiles can be edited, even if the TV is not active.
- Hotkeys may be 'OWNED' by other processes.  In my setup, F12 is one of the default keys assigfned 4th in line, but that's typically 'hidden' behind Steam's mapping of the key.  This is OK behavior, as we don't necessarily want to override other apps the user relies on actively, as DS is intended to be very background and near-dormant --> users can re-assign hotkeys as they wish in DS, so the control belongs to them.  There is currently hotkey devonfliction of DS hotkeys (more or less at the desktop level), but not for hotkeys that may have application-specific usage.
